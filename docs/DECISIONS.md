# Архитектурные решения

Короткий журнал решений, принятых при разработке, и их причин.

| # | Решение | Почему | Альтернатива |
|---|---|---|---|
| 1 | **Store — глобальная сущность** (общая для всех организаций), товары/ссылки/правила — тенантные | Конфигурация парсера (селекторы, rate limit, здоровье) одна для домена; rate limit должен считаться на домен, а не на клиента | Магазины на каждого клиента — дублирование настроек и неверный rate limit |
| 2 | Мультитенантность через `TenantQuerySet.for_org()` + `organization` FK (денормализован в `CompetitorOffer`) | Простая и проверяемая изоляция; тесты `test_tenancy.py` для веба и API | django-tenants (схема на клиента) — избыточно для этого масштаба |
| 3 | **Дедупликация снимков:** снимок пишется при изменении цены/старой цены/наличия + один «дневной контрольный»; каждая проверка — лёгкая запись `ScrapeRun` | История не раздувается (×20–50 меньше строк), графики остаются точными, `ScrapeRun` даёт метрики здоровья | Писать каждый снимок — дорого по диску и медленно для графиков |
| 4 | **Подозрительная цена** (×5 или 0) сохраняется как `is_suspicious`, оффер получает `pending_snapshot`, перепроверка через 10 мин; совпало (±1%) — подтверждаем, иначе `rejected` | Защита от мусорных алертов при сбое вёрстки/акции «1 сум» | Отбрасывать молча — теряем реальные обвалы цен |
| 5 | **Uzum через Playwright**, а не API | Исследование (окт. 2026): страница — Nuxt SPA, HTML без цены, JSON-LD Product пустой, `product:price:amount=0`; данные приходят из `graphql.uzum.uz` с анонимным токеном `id.uzum.uz` (внутренний API — не используем); старый `api.uzum.uz/api/v2/product/{id}` отдаёт 404. robots.txt разрешает `/ru/product/`. Отрендеренный DOM стабилен по `data-test-id` (`text__product-price`, `text__product-old-price`, `text__product-name`, `button__add-to-cart`) + meta `product:availability`; запасной путь — цена из `og:title` | Вызывать внутренний GraphQL — хрупко и этически сомнительно |
| 6 | Playwright запускается в **отдельном потоке** воркера | Sync API Playwright оставляет asyncio-loop в потоке → Django запрещает ORM (`SynchronousOnlyOperation`). Найдено при сквозной проверке через очередь `browser` | async-воркеры Celery — сложнее, без выигрыша |
| 7 | Rate limit — **token bucket в Redis (Lua)**, ёмкость ≤ 5; если ждать > 30 с — задача перепланируется (`countdown`), а не спит | Атомарно между всеми воркерами; воркер не простаивает | `time.sleep` в задаче — блокирует слоты воркера |
| 8 | Локи против дублей задач — `cache.add` (Redis) с TTL 5 мин на оффер и 55 с на планировщик | Атомарно, просто, без внешних библиотек | celery-once / redlock — лишняя зависимость |
| 9 | Планировщик: Beat раз в минуту выбирает «просроченные» офферы, ставит `next_check_at = now + interval ± 10%` и `countdown` 0–50 с | Равномерная нагрузка, нет «залпов» в начале часа | Отдельная periodic task на каждый оффер — тысячи записей в beat |
| 10 | Интервал проверки = `max(интервал ссылки, минимум тарифа)` | Тариф реально ограничивает нагрузку | Проверка лимита только в формах — обходится через API |
| 11 | Алерты: событие создаётся сразу, доставка — отдельной задачей раз в минуту с группировкой по товару и окном 30 мин | Анти-спам, одно сообщение «пачкой», легко добавить каналы | Отправка прямо из пайплайна — спам и связанность |
| 12 | Отправка в Telegram из Django — прямой вызов Bot API (`httpx`), а бот (aiogram) — отдельный процесс только для команд/кнопок | Воркеры не зависят от процесса бота; бот можно перезапускать | Шина событий бот↔Django — сложнее без пользы |
| 13 | Без `TELEGRAM_BOT_TOKEN` — «демо-режим»: алерты пишутся в лог, бот работает вхолостую, healthcheck зелёный | Проект запускается и проверяется без секретов | Падать без токена |
| 14 | Кнопка «Открыть товар» — URL-кнопка только для публичного `SITE_URL`; для localhost — callback | Telegram отклоняет URL-кнопки на localhost | — |
| 15 | i18n: язык выбирается cookie/профилем, **без URL-префиксов** | С `i18n_patterns` активация языка пользователя меняла префикс → 404 для пользователей с языком ≠ языку по умолчанию (найдено тестом) | Префиксы `/uz/…` — лишняя сложность для кабинета |
| 16 | Перевод: `.po` генерируется `makemessages` (в Docker), переводы хранятся в `scripts/translations.py`, `.mo` компилируется `polib` | Работает и на Windows без GNU gettext; переводы легко ревьюить | Только Rosetta/ручное редактирование .po |
| 17 | Демо-магазин — один FastAPI-сервис, три «магазина» по Host (сетевые алиасы Docker `*.demo`) и `?shop=` | Демонстрирует все адаптеры (JSON API, JSON-LD, CSS) без реальных сайтов | Три отдельных контейнера |
| 18 | Локально без Docker — loopback-алиасы `127.0.0.2–4` для трёх доменов демо-магазина | `*.localhost` не резолвится на Windows | Правка hosts-файла — требует прав администратора |
| 19 | Платежи — интерфейс `PaymentProvider` + `ManualProvider` (счёт, подтверждение в админке); Click/Payme — заготовки | Нужны договоры и ключи мерчанта | — |
| 20 | HTTPS — Caddy в prod-override | Автоматический Let's Encrypt без certbot-кронов | certbot + nginx (описан как альтернатива) |
| 21 | Статика — WhiteNoise внутри `web`, Nginx проксирует с кэш-заголовками | Один образ, нет общих томов между контейнерами | Общий том static между web и nginx |
| 22 | Локальная разработка на Python 3.10 (на машине не было 3.12), код совместим с 3.10+; образы — Python 3.12 | Проверка тестами в обоих окружениях | — |
| 23 | Тарифы по умолчанию: Start 400 000, Business 1 200 000, Enterprise 2 500 000 сум; Enterprise — проверка от 5 мин (демо использует его, чтобы изменения были видны за минуты) | Середина ценовых коридоров из бизнес-требований | — |
